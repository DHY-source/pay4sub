# 极简发卡小店

适合临时、小规模使用的自托管发卡网站：买家选择商品和数量、填写 QQ／手机号／邮箱后扫码付款，你核实到账后在后台点击“发卡”，系统一次发出所购数量的卡密。买家页面自动显示结果，也能凭同一联系方式查回。

固定商品单价，同一种商品每单可买 1–100 张，商品合计为单价乘数量。同渠道待付款金额冲突时，实际应付金额依次增加 0.01 元，最多加 0.10 元；买家必须按付款页应付金额付款。无需安卓监听、设备密钥、支付通知上报或金额通道解锁。

## 日常使用

1. 打开 `/admin`，用管理员密码登录。
2. 在“商品库存”添加商品，按一行一张导入卡密，并上架。
3. 在“设置”上传支付宝、微信收款码；仅配置了收款码的渠道可下单。店名和公告可自行修改。
4. 买家在首页点击“购买”，选择数量（默认 1 张）、填写联系方式和支付方式，核对商品合计后点击“去付款”。数量不能超过可用库存。按生成订单后的应付金额付款，勿抹零；付款备注填写该联系方式。
5. 你在收款账户中核对金额、备注和时间，找到后台对应订单后点“发卡”。系统扣减库存，买家自动看到卡密。
6. 买家关闭页面后，点击“查订单”，输入同一联系方式即可查看订单及已发卡密。

付款页、查订单中的付款码和后台收款码预览均可点击图片或“点击放大”打开大图。大图保留原图比例，支持“继续放大”到两倍并滚动查看、“适应屏幕”、关闭按钮、Esc 和点击遮罩关闭；手机可长按保存图片。订单过期、取消或已发卡后，已打开的付款大图也会自动关闭。

手机号、QQ 或邮箱在这里同时是查卡凭证；知道该联系方式的人也能查看对应卡密，不提供短信或邮件验证。金额区分只针对当前待付款订单；历史同金额订单保留，过期、取消或已发卡后金额可被重新使用。需要核对真实账单的渠道、金额、时间和备注，尤其是过期付款，不能仅凭通知金额判断订单。

## 设置自己的后台密码

登录 `/admin` 后，在“设置”中的密码表单填写当前密码、新密码和确认密码。新密码须为 **12–256 个字符**，两次填写一致。保存成功后，当前及其他浏览器的管理员会话都会退出，使用新密码重新登录。

密码只以哈希形式保存在数据库的私有认证表中，不出现在公开设置、商品接口或网页内容里。数据库首次初始化时采用部署配置的初始密码；后续重启、更新代码或修改 `.env` 中的初始密码哈希，都不会覆盖已经设置的密码。请保留当前密码供之后修改时验证。

## 库存和订单

- 库存数量由实际可用卡密计算。可用卡密可查看、编辑、删除，预留及已售卡密只读；批量导入会跳过重复卡密。
- 下单即按数量预留卡密，默认保留 30 分钟。关闭付款弹窗不会取消订单；超时或取消会释放该订单的全部预留库存。
- 每个商品合计在同一支付渠道可使用原价及加 0.01–0.10 元共 11 个金额档位，分配最低可用金额；跨商品、不同购买数量也检查实际应付金额冲突。11 个档位均被占用时返回“请稍后重新下单”，不创建订单、不占库存。微信、支付宝分别分配。
- 已发卡、取消或过期后释放金额档位。付款页、查单付款码和收款码放大界面均显示实际应付金额；放大图片时金额保持可见。付款弹窗到期后隐藏二维码；已经付款但超时的订单，可以由管理员核实后发卡。
- 超时补发只会使用可用库存，不会拿走其他订单预留的卡；缺货时先补卡再重试。整单发卡在一个事务内完成，数量不够不会部分发卡或扣减部分库存。
- 管理员可取消未发卡的待处理、已过期订单；重复取消不会重复释放库存，已发卡订单不能取消。取消后即可解除库存占用，不需要解锁金额。
- 重复点击发卡不会重复扣库存。买家和后台可查看及一键复制整单卡密；卡密只显示在网页，不另发 QQ、短信或邮件。
- 后台默认显示订单，支持按联系方式或订单号查询、状态筛选；库存和订单列表支持分页。

## 新站部署

服务器需要 Linux amd64、Docker Engine、Docker Compose 插件、Python 3.10+ 和可用域名。已有 `pay.dhy-api.com` 服务使用主机 Nginx 和 `compose.host.yaml`，请按 [DEPLOYMENT.md](DEPLOYMENT.md) 更新，不要直接套用下面的独立站点配置。

上传源码后在项目目录执行：

```bash
python3 scripts/setup.py --domain cards.example.com
docker compose up -d --build
docker compose ps
```

初始化会要求至少 12 个字符的后台密码，生成独立站点密钥并保存密码哈希。已有 `.env` 时拒绝覆盖。域名需解析到服务器，并开放 TCP 80/443；Caddy 自动提供 HTTPS。店铺在 `/`，后台在 `/admin`。

首次登录后配置商品、卡密和自己的收款码，再分别完成支付宝、微信真实小额付款和人工发卡测试。不要把示例域名当作实际地址。

本机预览：

```bash
python3 scripts/setup.py --local
docker compose -f compose.local.yaml up -d --build
```

访问 `http://127.0.0.1:8080` 和 `/admin`。本机配置只监听回环地址，使用独立数据卷；不要与 `compose.yaml` 合并。

## 从旧版本更新

1. 核对并处理未完成付款，先备份数据库和收款码，并单独保管原 `.env`。
2. 更新源码，保留原数据卷、管理员密码和 `SECRET_KEY`，不要重新运行初始化脚本。
3. 将既有 `.env` 中的 `ORDER_TTL_SECONDS` 改为 `1800`。旧的 `DEVICE_TOKEN`、`PAYMENT_COOLDOWN_SECONDS`、`AUTO_DELIVERY` 可移除，新配置不再使用。
4. 按原部署方式执行 `up -d --build`，检查健康接口和后台记录。已有主机 Nginx 的实例使用 [DEPLOYMENT.md](DEPLOYMENT.md) 中的完整命令。
5. 刷新浏览器，确认联系方式查询、库存管理和人工发卡。

升级保留商品、卡密、订单和收款码，旧订单按数量 1 迁移，原单价和应付金额保持不变；新增订单执行金额区分，升级前重复金额的待付款订单仍需人工核对。固定人工确认模式，旧自动设置及旧设备上报均不能触发发卡。旧订单没有联系方式时不自动补填，仍可凭原订单号和查询口令调用旧查询接口，或让管理员在后台查找。

`ORDER_TTL_SECONDS` 支持 60–1800 秒，默认 1800 秒；修改后需重新创建容器，单纯重启不会更新环境变量。

## 备份与恢复

```bash
docker compose exec -T app python scripts/backup.py
docker compose cp app:/app/data/backups ./backups
```

备份 ZIP 包含数据库和收款码，含明文卡密、联系方式及管理员密码哈希，应私密保存；不包含 `.env` 或源码。恢复前停止 `app`，先保存当前数据副本，将 ZIP 中的 `shop.sqlite3` 和 `qr/` 恢复到数据卷的 `/app/data`，移除旧 `shop.sqlite3-wal` 和 `shop.sqlite3-shm`，确保文件归容器 UID/GID `10001:10001` 所有，然后启动。不要在服务运行时覆盖数据库。恢复备份也会恢复备份时的管理员密码状态。

只有明确需要全新开店时才清空数据库。清空前将源码、`.env`、`compose.host.yaml`、数据库及收款码完整备份到站点目录之外的私有位置，并验证备份可读取；停止本服务的 `app` 后，再将 `shop.sqlite3` 和存在的 `shop.sqlite3-wal`、`shop.sqlite3-shm` 一并移出数据目录，保留 `qr/`。重新启动将初始化空数据库，商品、卡密、订单、店铺设置及数据库中的新密码都会重置，初次登录使用部署配置中的初始密码，再到后台设置自己的密码。普通更新不执行此步骤。

**不要执行 `docker compose down -v`，不要删除数据卷。** 正常更新和重启不会清空订单、库存或收款码。

## 开发验证和打包

后端为 Flask + SQLite，前端为原生 HTML/CSS/JavaScript，无 CDN 或前端构建步骤。接口见 [API.md](API.md)。

可选 [sub2api 自动兑换](SUB2API.md)：从自定义菜单进入并验证账户后，人工发卡会排队兑换现有库存码；关闭页面仍由后台 worker 处理。兑换码和结果持续可查。默认关闭，现在可直接通过管理页「设置 → sub2api 自动兑换」填写地址、检查连接并启用；加密密钥自动管理、保存无需重启。启用步骤、版本升级兼容和登录绑定限制见接入文档。

```bash
python -m unittest discover -s tests -v
node --test --test-timeout=10000 tests/store.test.js tests/admin.test.js tests/sub2api.test.js
node --check static/common.js
node --check static/store.js
node --check static/admin.js
python scripts/package_release.py
```

打包脚本仅包含网页服务源码、测试和文档，输出 `dist/card-shop-linux-amd64.tar.gz` 及 SHA256 文件；不包含业务数据、凭据、安卓源码或 APK。原 `android/` 文件可保留归档，极简版不再使用。

完整验证结果及可选真实浏览器复验见 [VERIFICATION.md](VERIFICATION.md)。
